# Infinity fresh application and photo-ID-only verification

The owner requested a launch fresh start. Old non-practice Infinity accounts are retired through access revocation; their trades, balances and original snapshots remain for audit. This is not trade-history deletion or a fabricated zero P&L. New approved Stage 1 accounts start at the standard $1,000 balance with no trades.

The audited reset supports a small explicit applicant-exemption list. Exempt applications and uploaded documents remain untouched; personal identifiers are stored only in the private action/database audit, never this public repository. Exempt submission does not itself approve a challenge.

Other existing users must submit their personal details again and obtain a new application approval. Retired accounts cannot be continued or reactivated. Old approvals cannot be reused, and the usual monthly cap and breach lockout apply to later fresh runs. Demo practice and documents are preserved. The reset refuses changed scope or open source exposure.

Photo ID and accurate residential address details remain required. A routine proof-of-address document/date is no longer required by the application or payout verification form, `submit_kyc`, or challenge submission checks. Storage ownership/object validation and owner review remain; missing or expired photo ID is not accepted. Existing documents stay private and are not deleted. No identity document is sent to a broker.

Terms 1.8 and Privacy 1.3 preserve the concurrent fair-process clauses and update the document requirement. Earlier legal documents and acceptances remain immutable. Publication must verify both forms and archived document hashes before activating the new current versions with migration `20261009004000`; until then the previous legal versions remain current.

The reset schema/operation are separate so deployment can install guards before the audited action. Do not rerun a reset with a new batch identifier merely to recover a website publishing delay. Repeating the same batch identifier is idempotent. Live classification criteria and E8 monitor permissions are unchanged.
